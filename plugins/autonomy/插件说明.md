# autonomy 插件说明：业务逻辑运行过程

> 本文以 `hermes_home/plugins/autonomy/` 源码及 208 已做过的实测为准。它说明当前设计和已验证的行为；未通过验收的部分在文末明确标注。

## 1. 插件是什么

autonomy 是 Hermes 的独立（`kind: standalone`）插件，用于在用户对话之外发起一轮自主思考。它不是网页服务，也不替换 Hermes 主对话或现有 `seed_memory`。

```text
用户消息
  │
  ▼
Hermes gateway ── pre_gateway_dispatch / pre_llm_call hook ──► 活动标记文件
  │                                                        LAST_USER_ACTIVITY
  │                                                        PREEMPT_NOW
  ├── 主模型（正常对话）
  │
  └── autonomy CLI / systemd tick
           │
           ├─ 配置、闸门、锁、预算、熔断、数据库
           ├─ GatewayClient ──► Hermes gateway run API ──► 自主模型/工具
           │                                      ├─ seed_search（召回）
           │                                      └─ seed_add（写入）
           ├─ seed_memory（由 Hermes/Agent 工具使用）
           └─ thoughts.log（UTF-8、写后只读）
```

入口是 `__init__.py: register(ctx)`：注册顶层 `hermes autonomy` 命令以及对话生命周期 hook。CLI 主要在 `cli.py`，向导在 `wizard.py`，单轮运行在 `tick.py` / `runner.py`。

## 2. 安装、启用与初始化

插件位于：`$HERMES_HOME/plugins/autonomy/`。在 `$HERMES_HOME/config.yaml` 启用：

```yaml
plugins:
  enabled: [autonomy]
```

推荐 schema：

```yaml
autonomy:
  model: qwen38-flash                 # null 表示继承主模型
  memory_provider: null               # null 表示沿用 Hermes 当前 memory.provider
  in_process_loop: false
  data_dir: /var/lib/hermes/autonomy_data
  thought_log: /var/lib/hermes/autonomy_data/thoughts.log
  quiet_s: 300
  limits:
    daily_tokens: 5000000
    circuit_threshold: 3
    circuit_cooldown_s: 1800
    memory_max: 1G
```

`config.py` 仍读取旧 schema（`model.inherit`、`memory.provider`、`budget`、`circuit`、`resources`、`paths`）以兼容既有配置；新向导应写新 schema。

`hermes autonomy init` 的设计顺序为：

1. 读取当前 Hermes 主模型，选择“继承”或单独的自主模型；
2. 向选定模型发测试请求；失败则应重新选择，不能继续下一步；
3. 列出/选择外置记忆配置，默认用当前 `memory.provider`；通过统一记忆对象进行写入与读回自检；
4. 设置宽松的资源额度并写回配置。

208 实测：主模型 `qwen38-flash-v100`、自主模型 `qwen38-flash` 的向导测试请求均返回 HTTP 200；记忆自检也曾成功。实际运行 CLI 应使用：

```bash
sudo -u <SERVICE_USER> -H env HERMES_HOME=/var/lib/hermes/hermes_home \
  /var/lib/hermes/app/venv/bin/hermes autonomy status
```

## 3. 一轮 tick 的完整过程

一次 tick 可由手工 `hermes autonomy tick` 或 systemd 服务触发：

0. **先取回记忆**：Runner 在发起任何模型调用前，通过当前 `memory.provider` 执行 `prefetch`，查询最近的、情绪强的、尚未完成的记忆，并结合最近事件摘要。结果作为提示词最前面的“醒来先回顾的记忆”段；模型必须先看到这段，再看到目标和事件，然后才开始思考。若 provider 未配置、返回空或读取异常，Runner 记录 `memory_prefetch` 降级事件，提示“暂无可回顾的记忆”并继续 tick，不让记忆故障拖垮自主思考。
1. **加载配置**：解析新 schema，必要时回退读取旧 schema；计算数据目录、模型、预算与日志路径。
2. **闸门检查**：检查 `STOP_AUTONOMY`、单实例锁、当日 token 预算、熔断状态，以及对话优先模式下用户是否仍在静默窗口内。
3. **模式判定**：`mode.decide_mode(main_model, autonomy_model)` 是唯一判定函数。两个不同模型为 `parallel`；继承、空值或相同模型为 `dialog_first`。
4. **组装提示词**：`prompt.py`/`solitude.py` 构造独处提示词；记忆回顾段固定在目标/事件之前，并明确“先回顾，再思考”。保留对 `/srv/protected-service` 与 Docker 的禁区说明，不引入必须输出 JSON 或字数限制。
5. **调用模型**：`GatewayClient` 通过本机 Hermes gateway 的 run API 调用模型与工具。208 实测 gateway health 地址是 `http://127.0.0.1:18787/health`。
6. **记忆工具**：确定性预取之外，Agent 仍可经 `seed_search` 召回更多记忆、经 `seed_add` 写入；Runner 不另建种子数据库。
7. **解析与日志**：模型输出尝试解析；JSON 失败时保留原文，不应因此计入失败。运行事件、预算、熔断状态写入 `autonomy.db`；思考文本写 `thoughts.log`，其头部记录本轮预取数量和 `seed_id` 列表，使用 UTF-8 且写后设只读。
8. **退出**：返回 `ok`、`stopped`、`blocked`、`yielded_user_active`、`preempted` 或明确失败状态。

## 4. 对话与思考的关系

### parallel

主模型和自主模型不同（例如主模型 `qwen38-flash-v100`、自主模型 `qwen38-flash`）时，思考与用户对话可以并行。用户消息仍记录活动，但不会因为正常对话直接终止不同模型的思考。

### dialog_first

只有一个模型时，用户优先。`pre_gateway_dispatch`、`pre_llm_call`、`on_session_start` hook 会更新：

- `LAST_USER_ACTIVITY`：最近用户活动时间；
- `PREEMPT_NOW`：要求正在执行的思考让出。

Runner 在开始与关键阶段检查这些标记；用户活动时暂停/让出，静默超过 `quiet_s` 后才可继续。

## 5. 预算与熔断

`guard.py: check_guard` 按顺序判断：熔断冷却中、半开探测、日 token 预算、正常允许。资源项包括：

- `limits.daily_tokens`：日 token 上限；非正值表示不限制；
- `limits.circuit_threshold`：连续失败阈值；
- `limits.circuit_cooldown_s`：冷却时间；
- `limits.memory_max`：进程资源保护上限。

冷却结束可半开探测。旧数据库可能遗留 `blocked` 状态：它可能来自旧版将认证/网关错误永久阻断的逻辑。处理前必须备份 `autonomy.db`，确认当前代码的 reset-circuit 实现及 CLI 接线后再清理，不能直接删除数据库冒充恢复。

## 6. 记忆如何读写

`memory_provider: null` 的含义是使用 Hermes 当前 `memory.provider`；本项目当前为 `seed_memory`。向导的 `memory_bridge.py` 用于列出配置、取得 Hermes 已初始化的记忆对象并做写/读回自检。

真正的自主会话记忆主要经 gateway Agent 的 `seed_search` 与 `seed_add` 工具完成。因此验证“A写、B读、网关重启后仍可读”必须在真实 Agent 会话中做：会话 A 写入唯一标记，会话 B 搜索该标记，重启 gateway 后再次搜索。未完成该实测前，不能仅凭本地单元测试宣称持久化验收已通过。

## 7. 命令与数据文件

| 命令 | 用途 |
|---|---|
| `hermes autonomy init` | 模型/记忆/额度向导与测试 |
| `hermes autonomy stop` | 创建停止标记 |
| `hermes autonomy resume` | 删除停止标记 |
| `hermes autonomy status` | 查看模式、模型、用量与熔断状态 |
| `hermes autonomy tick` | 手工执行一轮 |
| `hermes autonomy reset-circuit` | 若当前部署已完成该子命令接线，用备份后清理旧熔断；请以 `--help` 为准 |
| `hermes autonomy log -n 3` | 查看最近 3 轮思考摘要；`--full` 显示全文，`--seeds` 显示种子详情，`--tools` 显示工具/文件，`--json` 输出 JSON |

数据目录默认/推荐为 `/var/lib/hermes/autonomy_data`：

| 文件 | 含义 |
|---|---|
| `autonomy.db` | 运行、事件、预算和熔断状态 |
| `STOP_AUTONOMY` | 存在即停止/空转 |
| `LAST_USER_ACTIVITY` | 最近用户活动 |
| `PREEMPT_NOW` | 对话优先模式抢占请求 |
| `thoughts.log` | UTF-8 的只读思考日志 |

## 9. 常见问题

| 现象 | 排查 |
|---|---|
| `GatewayError` | 确认 health 是 `127.0.0.1:18787`；确认 tick 进程加载了 gateway 服务所需环境文件；只记录 HTTP 状态/错误类型，绝不打印 key。 |
| `status=blocked` | 检查 STOP 标记和 `autonomy.db` 熔断状态；先备份 DB，尤其注意旧版永久 blocked 遗留。 |
| tick 总是跑旧逻辑 | 检查 systemd `ExecStart`/`WorkingDirectory` 是否仍指向旧 `app/autonomy_pkg`。 |
| 中文变成 `????` | 使用 UTF-8 locale/SSH 与显式 `encoding='utf-8'`；历史乱码不可安全猜测还原。 |
| 定时器空转 | 检查 `STOP_AUTONOMY` 是否仍在，及 unit 是否加载正确环境。 |

## 已知问题与验收边界

- 一轮 tick 实测耗时约 5～12 分钟，仍偏慢。
- 对话优先模式的真实聊天暂停/续上目前仅做过逻辑验证，尚缺完整真人对话压测。
- Windows 本机的文件锁存在竞态风险；208 为 Linux，不受此项影响。

已关闭的历史问题：401/403/404 不再永久 `blocked`，改为普通失败计数与冷却恢复；启动时会迁移清理旧永久 blocked 状态。GatewayError 摘要含 `http_status`/`reason`。历史 thoughts.log 仅保留一行旧乱码，新写入已验证为 UTF-8。

### 降耗治理配置（本机已实现，待部署验收）

为避免单轮上下文和工具循环失控，新增/支持以下 `autonomy.limits` 配置（缺省值）：

- `prefetch_max_chars: 3000`：预取记忆整段注入上限；每条摘要最多 500 字，并按 `seed_id` 去重；超限会在事件和思考日志记录 `truncated=true`。
- `prefetch_timeout_s: 20`：预取隔离子进程超时；Unix 使用独立进程组，超时会终止进程组并回收，失败降级为暂无可回顾记忆。
- `run_max_seconds: 1200`：自主单轮软超时，低于 systemd 的 1500 秒；超时调用 `stop_run` 并记录 `run_timeout`。
- `max_turns: 30`：预留的网关最大轮数配置；当前 gateway run API 未确认支持该字段，因此本机以软超时为实际保护。

每轮思考日志和事件会记录 elapsed、prompt/completion/total token、预取 count/chars/truncated/seed_ids 及结束原因。提示词要求仅在预取记忆不足时调用 `seed_search`，避免重复搜索。

已知问题更新：历史线上单轮耗时/token 偏高，现已增加预取体积、子进程超时回收和单轮软超时上限；部署后仍需观察工具迭代次数和 token 趋势。

### 超时轮保全与新默认值

线上曾出现达到软上限后 token=0 且 thoughts.log 无内容的情况，原因是停止运行后仅保存超时状态，未提取网关已产生的部分结果。本机现已在超时/抢占路径尝试保留 assistant 文本、工具摘要和 usage，并以 `partial=true`、字符数、工具数、elapsed 和结束原因写入日志与事件；网关不返回部分内容时仍记录降级诊断。

- `run_soft_wrap_seconds: 1080`：18 分钟时尝试向运行中的 run 追加收尾提示；旧网关不支持追加接口时跳过并记录 unsupported。
- `run_max_seconds: 2400`：40 分钟硬上限，超时后优先保全部分产出。
- systemd `TimeoutStartSec: 3000`：比自主硬上限多 10 分钟。
- status 增加最近 10 轮摘要，便于查看耗时、结束原因和 token。

当前 gateway run API 支持查询运行状态，但本机客户端未发现稳定的历史 assistant/events 拉取或追加消息能力；因此保全采用状态响应中可用的 output/text/content/usage/tool_calls 字段，并对缺失内容明确记录降级。
